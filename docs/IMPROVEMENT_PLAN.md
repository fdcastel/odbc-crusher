## How to keep this plan updated

This document is the single work queue for the project. **Update it in the same commit as the change it describes** — never in a follow-up commit, or it drifts.

**Every time you finish a task:**

1. Set **Status** to `✅ DONE` (only once the fix is implemented *and* tested — see below).
2. Fill the **Commit** column with the short hash (`git rev-parse --short HEAD`).
3. Rewrite the **Details** cell to say what was *actually* done, not what was planned. If the implementation diverged, say so and why.
4. If the work uncovered new problems, add new rows rather than widening an existing task.

**Status values** — use exactly these:

| Symbol | Meaning |
|---|---|
| ✅ DONE | Fix implemented **and** tested. Not DONE until a test would catch its regression, or Details explains why no test is possible. |
| 🔧 IN PROGRESS | Partially implemented or underway. Note in Details what is left. |
| ❌ OPEN | Not yet addressed. |
| ⏯️ DEFERRED | On hold until another task finishes. Name the blocking task ID in Details. |

**Rules that keep the plan honest** — the previous plan broke each of these at least once:

- **Never mark a task DONE on the strength of a plan entry. Re-read the code.** Prior §2.1 claimed "migrated all 23 test files" while `param_binding_tests.cpp` was 3-of-26 migrated. Prior §3.2/§3.6 claimed "every public entry point takes `HandleLock`" while `SQLFreeStmt` takes none.
- **Marking a task DONE and then re-loosening it elsewhere is not DONE.** Prior §7.10 stayed ✅ while §8 immediately relaxed the very assertion it had tightened.
- **"Implicitly addressed by another task" is not a resolution.** Prior §2.8 was closed that way and is untouched in the code.
- **Never delete a row.** If a task turns out to be wrong, keep it and change Details to explain the reversal.
- **Keep `README.md` counts in sync** whenever probe counts, pass rates, or the driver matrix change (H1–H3).
- **This file now lives in the tracked `docs/` directory** (**H8**, done). `tmp/` remains gitignored and is for scratch artifacts, clones and triage output only — never for living documents.

**Suggested order**: A (result integrity) → D (mock driver) → B (taxonomy) → E (build) → C (duplication) → F/G/H.

## Part J — Recommended execution order

All 120 tasks, sequenced. The order is driven by **dependencies and risk**, not by severity: several high-severity items are deliberately late because fixing them earlier would be unverifiable or would be undone by a later refactor.

Three principles shape it:

1. **Build the safety net before changing behaviour.** Right now the mock's own tests avoid nearly every broken surface, the Linux canary tolerates 29 non-passing probes, and the JSON output cannot be parsed by a machine. Change probe verdicts before fixing that and you have no way to tell a fix from a regression.
2. **Land the shared helper before the twenty call sites that need it.** Four findings (**A1**, **A2**, **A4**, **B3**) are each a one-line change repeated dozens of times. Doing them by hand first means doing them twice.
3. **Fix the mock before chasing the Linux gap.** Several §8 clusters are probably *symptoms* of mock defects found in this review (**D22**, **D24**, **D25**), not of a platform issue. Chasing them first risks building platform-specific workarounds for bugs that are not platform-specific.

**Do not start with**: the big refactors (**C8**, **C9**, **D18**, **D31**) — they are the right destination but they move code you have not yet made correct; the §8 Linux clusters (**I1**–**I5**); or implementing `SQLError`, which Part 0 shows is not the blocker.

Each phase below is independently shippable and leaves the tree green. Phase 8 is documentation and can be done by anyone at any time, in parallel with everything else.

## Appendix — Reproducing the measurements

```bash
# Full local build + test (Windows, MSVC)
cmake -B mock-driver/build -S mock-driver && cmake --build mock-driver/build --config Debug -j 8
ctest --test-dir mock-driver/build -C Debug --output-on-failure          # 107/107
cmake -B build && cmake --build build --config Debug -j 8
ctest --test-dir build -C Debug --output-on-failure -L unit              # 27/27 (7 skip)
ctest --test-dir build -C Debug --output-on-failure -L e2e               # 14/14

# The reference fixture — expect 195/195 on Windows/macOS
build/src/Debug/odbc-crusher.exe "Driver={Mock ODBC Driver};Mode=Success;Catalog=Default;ResultSetSize=10;" -o json -f report.json

# ...and again in Release. CI's e2e slots run Release, and it is materially
# faster: a timing-sensitive probe (A12) passed in Debug and broke every CI
# platform because the phase it measured fell below a threshold only in the
# optimised build. Register the Release mock first, then put Debug back.
cmake --build build --config Release -j 8 && cmake --build mock-driver/build --config Release -j 8
mock-driver/install/register.ps1 -DriverPath mock-driver/build/Release/mockodbc.dll
build/src/Release/odbc-crusher.exe "Driver={Mock ODBC Driver};Mode=Success;Catalog=Default;ResultSetSize=10;" -o json -f report-release.json
mock-driver/install/register.ps1 -DriverPath mock-driver/build/Debug/mockodbc.dll

# E1 / D16 — surface the warnings the current CMake configuration hides
cmake -B cmake-build-warn-app  -DCMAKE_CXX_FLAGS="/W4 /EHsc" && cmake --build cmake-build-warn-app  --config Debug -j 8
cmake -B cmake-build-warn-mock -S mock-driver -DCMAKE_CXX_FLAGS="/W4 /EHsc" && cmake --build cmake-build-warn-mock --config Debug -j 8

# D9 / F11 — source-level guards, runnable locally (both also run in CI)
python mock-driver/tools/check_entry_guards.py      # every entry point wrapped

# G1 — the documented pipe usage
build/src/Debug/odbc-crusher.exe "Driver={Mock ODBC Driver};Mode=Success;" -o json | python -c "import sys,json; json.load(sys.stdin)"

# A2 — NOTE: this command is obsolete since A2 landed. The bare literals are
# still in the source, but they are now arguments to
# TestBase::literal_select_variants(), which appends the FROM RDB$DATABASE and
# FROM DUAL forms. Grep for a bare `stmt.execute("SELECT ` instead — that is
# the shape that bypasses the helper.
# Original command, kept for the record:
cd src/tests && for f in *_tests.cpp; do
  bare=$(grep -oE '"SELECT [^"]*"' "$f" | grep -vi ' FROM ' | wc -l)
  fb=$(grep -c 'RDB\$DATABASE' "$f")
  [ "$bare" -gt 0 ] && [ "$fb" -eq 0 ] && printf "%-32s %s bare selects, 0 fallbacks\n" "$f" "$bare"
done

# C1 — run_test adoption per file
for f in *_tests.cpp; do printf "%-32s run_test=%-3s make_result=%-3s clock=%s\n" "$f" \
  "$(grep -c 'run_test(' $f)" "$(grep -c 'make_result(' $f)" "$(grep -c 'high_resolution_clock::now()' $f)"; done

# D2 — compare the Windows export list against what the sources define
grep -oE '^\s+SQL[A-Za-z0-9]+' mock-driver/src/mockodbc.def | tr -d ' \r' | sort -u > /tmp/exported.txt
grep -rhoE 'SQLRETURN\s+SQL_API\s+[A-Za-z0-9_]+\s*\(' mock-driver/src --include=*.cpp \
  | grep -oE 'SQL[A-Za-z0-9_]+' | grep -v '^SQL_API$' | sort -u > /tmp/defined.txt
comm -23 /tmp/defined.txt /tmp/exported.txt   # 38 ANSI entry points exported on Linux only
```
